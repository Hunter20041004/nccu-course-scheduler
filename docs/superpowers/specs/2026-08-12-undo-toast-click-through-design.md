# 復原提示不遮擋操作 — 設計

日期：2026-08-12

## 問題

學生刪除課程、清空課表或套用 AI 方案後，畫面右下角會顯示 15 秒復原提示。提示目前整塊都會接收滑鼠與觸控事件，因此即使學生不是要按「復原」，也無法操作被提示文字區蓋住的課程按鈕。

## 核可方案

保留提示的位置、外觀、15 秒期限與資料復原邏輯，只調整互動範圍：

- 提示容器不接收點擊，學生可操作文字區後方的介面。
- 「復原」按鈕單獨接收點擊，維持既有復原功能與 44px 最小操作尺寸。
- 不移動提示、不改文案、不改排課資料格式，也不改任何 AI 功能。

這是最小、可逆的修正。把提示移到頁面頂部會讓已捲到候選清單下方的學生看不到；改到其他角落則只是轉移遮擋位置。

## 技術與資料流

`capturePlannerUndo()` 仍負責保存排課快照並顯示提示；CSS 只改變瀏覽器如何分派點擊事件。學生按「復原」時，既有 `undo.restore()` 仍還原同一份快照。這次不新增外部服務、資料欄位或套件。

## 驗收

1. 先新增一個會失敗的畫面結構測試，要求提示容器可穿透點擊、復原按鈕仍可互動。
2. 修改最少量 CSS，讓該測試通過。
3. 真實瀏覽器重現提示覆蓋課程操作的情境，確認後方按鈕可操作，且「復原」仍能還原。
4. 桌機 1280×800 與手機 375×812 各完成兩輪截圖自檢，確認不破版、無橫向捲動、焦點與狀態仍清楚。
5. 跑完整測試、建置、語法檢查與政大官方資料連線測試；合併 `main`、推送並部署原正式網址後，再從使用者視角驗收。

## 風險與限制

- 提示仍會視覺上覆蓋小部分內容，但文字區不再阻擋操作；「復原」按鈕本身必須保持可點，所以它占用的 44px 區域仍是唯一互動區。
- 真實 Gemini 推薦、AI 比較與截圖辨識仍需要有效的使用者 API Key。本修正不把缺少測試 Key 誤當成程式故障。
- 不增加成本，也不改變 API Key 只保留在目前分頁的安全設計。
